# /tofugraph:3d — 3D 그래프 뷰어

내 창고의 노트 연결망을 3D 로 봅니다. 기본은 **localhost 서버 모드** — `http://127.0.0.1:8401/` 에 상시 떠 있고, 창고가 바뀌면 **브라우저 새로고침만 하면 최신 그래프**가 나옵니다(요청마다 DB 변경을 감지해 자동 재조립). 서버를 못 띄우는 환경에서만 단일 HTML 파일로 폴백합니다.

## 실행 절차 (에이전트용)

### 1순위 — 서버 모드 (기본)

1. **이미 떠 있는지 먼저 확인**: `curl -s -o /dev/null -w '%{http_code}' --max-time 3 http://127.0.0.1:8401/` 가 `200` 이면 서버가 이미 떠 있다 — 새로 띄우지 말고 2번(브라우저 열기)으로 간다.
2. **백그라운드로 기동**: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/graph3d/serve_viewer.py" --port 8401` 을 **백그라운드**(하네스의 백그라운드 실행 기능 또는 `nohup ... >/tmp/tofugraph-viz.log 2>&1 &`)로 띄운다 — 포그라운드로 돌리면 터미널이 잡혀 다음 작업이 막힌다. 기동 직후 위 curl 로 `200` 을 실측 확인한다(첫 조립에 창고 크기에 따라 수십 초 걸릴 수 있음 — `503`/무응답이면 몇 초 간격으로 재확인). 포트가 점유돼 있으면 서버가 안내하는 대로 `--port 8402` 등으로 옮기고 이후 주소도 그 포트로 맞춘다.
3. **띄우고 끝내지 않는다 — 브라우저까지 연다**: macOS `open http://127.0.0.1:8401/` / Windows `start "" http://127.0.0.1:8401/` / **WSL**(`/proc/version` 에 microsoft 가 보이거나 `$WSL_DISTRO_NAME` 이 있으면) `explorer.exe "http://127.0.0.1:8401/"` — WSL 에서 `xdg-open` 은 브라우저가 안 뜨고 매달리므로 쓰지 않는다 / 그 외 Linux `xdg-open http://127.0.0.1:8401/`. 사용자가 명령 하나로 "내 창고 그래프가 화면에 떠 있는 상태"까지 도달해야 한다.
4. 마지막에 사용자에게 두 줄 알려준다: ① 주소(`http://127.0.0.1:8401/`) — "창고를 고친 뒤엔 새로고침만 하면 반영됩니다" ② 서버 끄는 법(백그라운드 프로세스 종료 방법 또는 로그 위치).
5. 자동 열기가 실패한 환경에서만 "브라우저에서 이 주소를 여세요" 안내로 대체한다. 단 WSL 의 `explorer.exe` 는 창이 정상으로 떠도 종료코드 1 을 돌려줄 때가 있으므로 **종료코드로 실패를 판정하지 말 것** — 에러 출력이 있거나 사용자가 안 떴다고 할 때만 안내로 대체한다.

### 2순위 — 단일 HTML 파일 폴백 (서버를 못 띄울 때만)

서버 기동이 실패(파이썬 소켓 제한·정책 차단 등)했거나 사용자가 "파일로 달라"고 하면: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/graph3d/export_data.py"` 로 데이터를 추출하고 → `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/graph3d/build_viewer.py"` 로 단일 HTML(라이브러리·데이터 전부 내장 — 서버·네트워크 불필요)로 조립한 뒤, 위 3번과 같은 OS 분기(macOS `open` / Windows `start` / WSL `explorer.exe "$(wslpath -w <생성된.html>)"` + 종료코드 단서 동일)로 그 파일을 브라우저에 띄우고 경로를 알려준다. 이 파일은 만든 시점의 스냅샷이라 창고가 바뀌면 다시 만들어야 한다는 점도 한 줄 덧붙인다.
